# Архитектура

## Компоненты

Проект состоит из браузерной игры на TypeScript/Phaser, интерфейса на DOM/CSS и Node-сервера с SQLite. Vite собирает клиент в `dist/`. LLM и внешний сервис генерации во время игры не вызываются.

| Компонент | Ответственность |
|---|---|
| [src/main.ts](../src/main.ts) | Запуск Phaser, состояние экранов, комнаты, пауза и переходы |
| [src/core/](../src/core/) | Чистые правила, типы, баланс, сложность, комнаты, регистрация, помощь ПАК |
| [src/game/RoomScene.ts](../src/game/RoomScene.ts) | Физика Arcade, взаимодействия, противники и отрисовка сцены |
| [src/game/input.ts](../src/game/input.ts), [audio.ts](../src/game/audio.ts) | Клавиатура и синтез звуков через Web Audio |
| [src/ui/](../src/ui/) | Меню, форма, HUD, пауза, паспорт, рейтинг и окно сотрудника |
| [src/assets/](../src/assets/) | Генераторы графики, локальные изображения и шрифты |
| [server/start.mjs](../server/start.mjs) | Раздача только файлов `dist/` и подключение API |
| [server/leaderboard.mjs](../server/leaderboard.mjs) | Валидация запросов, API и хранение в SQLite |
| [server/vite-plugin.mjs](../server/vite-plugin.mjs) | Тот же API для Vite dev и preview |
| [server/export-passports.mjs](../server/export-passports.mjs) | Локальная выгрузка привязанных паспортов в CSV |

## Игровое состояние

`RunState` содержит сложность, бюджет, результаты комнат, полученные модули и использование помощи ПАК. Контакты игрока хранятся отдельно в `PlayerEntry`.

`getRooms(difficulty)` клонирует шаблоны комнат и применяет состав целей выбранной сложности. `RoomRules` управляет таймером, SLA, энергией, ОГН, наградами и условиями завершения. Сцена определяет столкновения и попадания, затем обращается к правилам.

При входе в комнату `main.ts` сохраняет снимок `RunState`. Повтор после провала восстанавливает этот снимок. На экране результата успешной комнаты отсчитываются пять активных секунд, после чего игра продолжает маршрут. Финальный экран отправляет результат через `Leaderboard`.

В dev-режиме `window.__uptime` предоставляет диагностический снимок для браузерных тестов. В production-сборке этот блок отсутствует. Диагностика не содержит регистрационных контактов.

## Оформление

Без параметра адреса выбирается К2 НейроТех. Значение `?theme=aihub` выбирает тёмную тему AI Hub; любое другое значение оставляет К2. Общие правила, физика и ресурсы сцены не зависят от темы.

Палитры и шрифты определены в [theme.css](../src/ui/theme.css), основные состояния и раскладка — в [style.css](../src/style.css), дополнительные стили — в `src/ui/*.css`. Локальные ресурсы включаются в сборку. Сведения о шрифтах и сторонних компонентах — в [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

## API

Все маршруты находятся на том же origin, что и игра. Ответы API возвращаются с `Cache-Control: no-store`.

| Метод и маршрут | Назначение |
|---|---|
| `GET /api/leaderboard?difficulty=easy&current=<uuid>` | До 100 публичных строк, текущее место и общее число видимых записей; `current` необязателен |
| `POST /api/runs` | Сохранение результата; возвращает рейтинг |
| `POST /api/runs/<uuid>/passport` | Привязка номера бумажного паспорта с токеном этой попытки |
| `GET /api/admin/leaderboard` | Постраничный список для сотрудника с фильтрами `difficulty`, `showHidden`, `page` |
| `POST /api/admin/runs/<uuid>/visibility` | Скрыть или вернуть результат: JSON `{ "hidden": true }` или `false` |

Значения сложности в API: `easy`, `standard`, `hardcore`. Сотрудник передаёт ключ через `Authorization: Bearer …`. Клиент держит его только в памяти открытого окна управления.

Для записи результата нужны UUID попытки, сложность, целочисленный бюджет, четыре результата с уникальными ID комнат и регистрационные поля. Повтор идентичной записи с тем же ID не создаёт новую строку; изменённое содержимое даёт конфликт. Сервер проверяет структуру данных, но не пересчитывает игру. Ограничения доверия к клиенту описаны в [DEPLOYMENT.md](DEPLOYMENT.md#данные-и-ограничения).

## Хранение

Путь базы задаёт `LEADERBOARD_DB_PATH`; по умолчанию это `data/leaderboard.sqlite` относительно рабочего каталога процесса. При открытии включается WAL, создаются таблицы и добавляются недостающие контактные столбцы.

| Таблица | Содержимое |
|---|---|
| `runs` | Результат, регистрационные данные, версия и время согласия, время приёма, хеш содержимого |
| `run_claims` | SHA-256 токена привязки паспорта |
| `run_passports` | Номер паспорта, уникальный нормализованный номер и время привязки |
| `run_visibility` | Признак скрытия и время изменения |

Скрытие меняет только публичную видимость. Исходная запись, контакты и паспорт остаются в базе и выгрузке. Подробности доступа, резервного копирования и данных — в [DEPLOYMENT.md](DEPLOYMENT.md).
