# Сервер, данные и развёртывание

## Локальный сервер

```sh
npm ci
npm run build
npm start
```

По умолчанию игра доступна на `http://127.0.0.1:4173`. `server/start.mjs` раздаёт файлы из `dist/` и обслуживает `/api/`. Одна статическая папка `dist/` не обеспечивает сохранение общего рейтинга и паспортов.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `HOST` | `127.0.0.1` | Адрес привязки сервера |
| `PORT` | `4173` | Порт HTTP |
| `LEADERBOARD_DB_PATH` | `data/leaderboard.sqlite` | Файл SQLite; относительный путь отсчитывается от рабочего каталога процесса |
| `LEADERBOARD_ADMIN_TOKEN` | Не задана | Ключ управления рейтингом, от 24 до 256 символов |

Переменные передаются окружением процесса. Автоматической загрузки `.env` сервер не выполняет. Создаваемый каталог базы получает режим `0700`, файл — `0600`; доступ к каталогу и резервным копиям также зависит от настроек ОС.

## Публикация на сервере

Для размещения на ВМ установите Node.js 24, зависимости и соберите клиент. Запускайте `npm start` из каталога репозитория под отдельным пользователем и менеджером процессов. Держите постоянную базу отдельно от заменяемого каталога сборки, укажите её через `LEADERBOARD_DB_PATH`.

При публикации через домен настройте HTTPS на обратном прокси и направьте на Node-сервер как страницу, так и `/api/`. Сохраните исходный заголовок `Host`: обработчик записи сравнивает его с `Origin`, когда этот заголовок есть. Адрес `127.0.0.1` подходит для прокси на той же ВМ; при другой схеме задайте подходящий `HOST` и сетевой доступ.

Это описание способа запуска. Репозиторий не содержит готовой конфигурации конкретной ВМ, домена или сервисного менеджера.

## Обновление и резервная копия

Перед заменой работающей версии сохраните предыдущую сборку и согласованную копию базы. Простой вариант: остановить процесс, сохранить файл SQLite вместе с оставшимися файлами `-wal` и `-shm`, затем обновить код и сборку. Не копируйте один основной файл открытой WAL-базы как гарантированно полную резервную копию.

После запуска проверьте главную страницу, чтение рейтинга, сохранение вымышленного результата и существующие записи. Если схема данных меняется, сохраняйте резервную копию до первого старта новой версии: сервер создаёт таблицы и выполняет предусмотренные миграции при открытии базы.

## Управление рейтингом

Задайте `LEADERBOARD_ADMIN_TOKEN` в окружении сервера и откройте окно «Управление лидербордом» через интерфейс. Без корректно настроенного ключа административный API недоступен.

Сотрудник может просматривать результаты по сложности, показывать скрытые записи, скрывать и возвращать их. Скрытие не удаляет контакт, результат или паспорт. Ключ передаётся в заголовке авторизации, хранится в памяти открытого окна и сбрасывается при выходе или закрытии. Не включайте его в исходники, ссылку на игру или публичные артефакты.

## Выгрузка паспортов

Локальная утилита выгружает только результаты с привязанным номером паспорта:

```sh
node server/export-passports.mjs data/leaderboard.sqlite passports.csv
```

Укажите новый файл: утилита отказывается перезаписывать существующий. CSV содержит номер паспорта, имя, фамилию, компанию, контакты, сложность, число комнат, бюджет, время и ID попытки. Используются UTF-8 с BOM, разделитель `;` и экранирование значений, похожих на формулы электронных таблиц. Файл создаётся с режимом `0600` и не предназначен для публичного размещения.

## Данные и ограничения

Это описание текущего поведения кода, а не заключение о юридической готовности мероприятия.

- Форма явно просит использовать вымышленные данные. Обязательны имя, фамилия, компания, телефон или Telegram и отметка согласия; почта необязательна.
- До финала данные регистрации находятся в памяти вкладки. При финальном сохранении сервер записывает их вместе с результатом в SQLite. Возврат в меню очищает форму, но не удаляет серверную запись.
- Публичный рейтинг возвращает имя, компанию, число пройденных комнат, бюджет, место и ID попытки. Фамилия, телефон, Telegram, почта и поля согласия не входят в публичный ответ. Административная таблица дополнительно показывает фамилию и время результата; CSV паспортов включает контакты.
- Версия согласия в коде — `draft-game-registration-2026-10-04`. В форме есть внешние ссылки на документы К2Тех. Эти ссылки открываются отдельно и не нужны для загрузки игры; их наличие не подтверждает согласование всех условий конкретного запуска.
- Сервер проверяет формат и размер записи, допускает только известные сложности и комнаты, защищает повторную запись по ID и проверяет `Origin`, если он передан. Он не пересчитывает игровой результат и не подтверждает принадлежность контакта участнику.
- Античит, ограничение частоты публичных записей и проверка «один человек — один результат» не реализованы. Один участник может занимать несколько строк. В коде нет автоматического срока удаления контактов.

Для призового запуска остаются отдельные решения по правилам участия и определения победителей, проверке результатов, текстам согласия, публичному показу имени/компании, доступу к контактам и срокам хранения. Текущий код сам по себе не подтверждает готовность к такому запуску.
