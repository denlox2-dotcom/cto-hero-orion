# Разработка с Creator

По описанию автора, игра создавалась в контуре ПАК-AI через Creator. Постановкой служил документ ТЗ; маркетологи оставляли уточнения в Word в Nextcloud, агент вносил доработки и разворачивал результат на ВМ. Автор направлял работу и предоставлял домен. Материалы статьи и оригиналы ТЗ хранятся отдельно от этого репозитория.

## Контур inference

Конфигурация по данным автора:

| Параметр | Значение |
| --- | --- |
| Модель | Qwen 3.8 27B |
| Формат весов | BF16 |
| GPU | 4×NVIDIA H100 |
| Движок | vLLM |
| Управление inference | Dynamo поверх vLLM |
| Контекстное окно | Максимальное для модели |

Точный model ID, численный размер окна и параметры параллелизма не опубликованы. Готовый конфиг развёртывания и измерения производительности в этот пример не входят.

Официальные материалы: [vLLM](https://docs.vllm.ai/en/latest/), [Dynamo](https://github.com/ai-dynamo/dynamo), [Qwen](https://github.com/QwenLM), [К2 НейроТех](https://k2neuro.tech/). Эти ссылки дают сведения о проектах; описание использованного контура приведено выше по данным автора.

## Запуск игры

Игра выполняет правила локально в браузере. Графика, шрифты и код загружаются из сборки; рейтинг использует Node-сервер и SQLite. Ключи модели и inference-сервер для игрового процесса не нужны. Внешние ссылки формы открываются только по действию пользователя.

## Следующие итерации

Задавайте наблюдаемое поведение: экран, действие игрока, ожидаемый результат и ограничения. Сопоставляйте изменения с [правилами](GAMEPLAY.md) и фактическим кодом, затем выполняйте подходящие [проверки](DEVELOPMENT.md).

Изменения баланса проверяйте на маршруте игрока, формы — с вымышленными данными, API — с учётом публичных и приватных полей. Расход токенов и число итераций приводите только при наличии исходных данных.
